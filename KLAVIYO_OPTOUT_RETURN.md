# Klaviyo email opt-out return

Opening an existing customer in either staff view, or selecting **Refresh email status**, reads that customer's current Klaviyo profile and saves the result in Nazar CRM. This is an on-demand reconciliation, not a continuously running webhook or scheduler. Nothing sends a message, subscribes a person, or changes Klaviyo.

The server resolves the email from `crm_klaviyo_status_v1` under the existing active staff session. It reads the global profile first, so an unsubscribe remains observable after someone leaves the VIP list. Confirmation additionally requires membership in list `UeJynm`. A missing profile or membership is not treated as an unsubscribe. Missing/malformed subscription fields, ambiguous identities, timeouts and provider errors cannot grant consent or overwrite saved evidence.

`record_klaviyo_status_v1` is service-role-only. It locks the matching Nazar customer, verifies the email still matches, and stores an observation in private `core.klaviyo_email_observations`. A verified unsubscribe, global suppression or Nazar VIP list suppression sets the existing local `email_status` to `unsubscribed`, records the block time, and adds one `klaviyo_readback` suppression evidence event. The existing evidence label `admin_suppression` describes the enforced local block; the note distinguishes the provider's unsubscribe from a delivery suppression. Unsubscribe and suppression are distinct provider statuses, even though both prohibit local email marketing.

Subsequent reads and form submissions cannot remove the block or grant local consent. Older responses cannot replace newer snapshots; a late negative response still enforces a conservative block. Re-enabling someone is a separate reviewed operation; this feature has no unblock control. Do not edit an opt-out into `subscribed`, reimport it, or use the public subscribe endpoint to circumvent it.

The staff panel shows current provider status, CRM save success/failure, the permanent block and dated prior evidence if a lookup fails. Confirmation is not permission for staff to send. Future CRM exports or sending code must exclude local `unsubscribed`/suppressed customers and test records, and verify current Klaviyo list, consent and suppression immediately before sending. The website currently has no general CRM marketing sender; Klaviyo's own unsubscribe/suppression remains authoritative for sends from Klaviyo. This readback does not provide instant cancellation propagation while no profile is being checked, and does not complete the separate designated inbox/delivery/unsubscribe-link acceptance test (10.07).

Apply `database/20261015_klaviyo_optout_return.sql` to Nazar-production before deployment. Reuse Production secrets `SUPABASE_SECRET_KEY`, `KLAVIYO_CRM_READ_KEY` and public `VITE_SUPABASE_ANON_KEY`; no new key or broadened Klaviyo scope is required. Private keys never enter the browser. Roll back the application to the previous release if required; retain the additive observation table and all opt-out evidence. No destructive database rollback is needed.

Validation: `tests/crmKlaviyoStatus.test.mjs` uses mocked providers. `tests/klaviyoOptout.rollback.sql` tests real PostgreSQL permissions, idempotent evidence and suppression persistence without leaving synthetic rows or sending email. Run the full rollback script, never only the middle statements.
